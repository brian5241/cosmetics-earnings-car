## 1. 연구 질문

> 실적 발표에 담긴 여러 항목 중, 발표 직후 주가 반응과 관련이 큰 항목은 무엇인가?

부차 질문:
- 시장은 외형 성장(매출)에 반응하는가, 수익성 개선(마진)에 반응하는가?
- 발표 전 선반영 정도가 발표 후 반응 크기를 줄이는가?

## 2. 분석 설계

### 2.1 종속변수: CAR (Cumulative Abnormal Return, 누적초과수익률)

발표 직후 주가 움직임에서 **시장 전체 요인을 제거한 몫**만 남긴 값.

```
AR  = 실제 수익률 − 기대 수익률(α + β × 시장수익률)
CAR = 이벤트 윈도우 구간의 AR 합계
```

| 구분 | 설정 |
|---|---|
| 주력 윈도우 | CAR[0, +1] |
| 보조 윈도우 | CAR[0, +5], CAR[0, +20] |
| 추정 윈도우 | [-250, -30] |
| 벤치마크 | 시장지수 + 섹터지수 |

**왜 [0,+1]인가**
하루만 보면 우연에 휘둘리고, 장 마감 후 발표는 반응이 다음 거래일에 나온다. 이틀을 묶어 둘 다 흡수한다.

**왜 추정 윈도우에서 -30일을 빼는가**
발표 직전 구간은 이미 실적 기대감에 오염되어 있다. 이 구간으로 베타를 추정하면 "정상 수익률" 기준 자체가 왜곡된다.

**왜 섹터지수를 함께 쓰는가**
시장 요인만 제거하면 섹터 공통 요인이 남는다. 발표일이 특정 시기에 몰려 있어 이 요인은 상쇄되지 않는다.

### 2.2 무엇을 통제하고 무엇을 통제하지 않는가

판단 기준: **랜덤이면 통제하지 않고, 체계적이면 통제한다.**

| 교란 요인 | 성격 | 처리 |
|---|---|---|
| 시장 전체 등락 | 체계적 (전 종목 공통) | 시장모델로 제거 |
| 섹터 업황 뉴스 | 체계적 (섹터 공통) | 섹터지수 팩터 추가 |
| 실적과 동시 발표된 배당·자사주 공시 | 체계적 (실적과 동반 경향) | 더미 처리 또는 표본 제외 |
| 발표일 우연히 나온 개별 종목 뉴스 | 랜덤 | 통제하지 않음 — 표본 평균이 상쇄 |

개별 이벤트마다 "왜 올랐는가"를 설명할 필요가 없다. 답하려는 질문은 "이 종목이 왜 올랐나"가 아니라 **"특정 항목이 좋은 그룹은 평균적으로 더 오르는가"**이기 때문이다. 표본이 충분하면 랜덤 교란은 평균에서 사라진다.

**예외**: 랜덤 교란이라도 대형 M&A·유상증자 같은 극단 케이스는 평균을 끌고 간다. CAR 상하위 이벤트는 개별 확인 후 실적 무관 대형 이벤트면 제외 또는 윈저라이징.

## 3. 유니버스 선정

### 3.1 정의 확정 과정

섹터 정의를 두 가지로 놓고 비교했다.

| | 협의 (화장품) | 광의 (K뷰티) |
|---|---|---|
| 범위 | 브랜드 · ODM · 유통 | + 메디컬에스테틱 · 미용기기 · 톡신 |
| 종목 수 | 11 | 20+ |
| 실적 동인 | 소비 수요로 통일 | 소비 수요 / 장비 판매 / 허가·소송 혼재 |

**광의 채택 시 문제**: 톡신·미용기기 종목은 실적보다 소송·허가 뉴스에 주가가 크게 반응한다. 이는 랜덤 노이즈가 아니라 해당 종목군에 체계적으로 붙어 있는 요인이므로 "표본 평균이 상쇄한다"는 논리가 성립하지 않는다. 섹터를 한정한 목적 자체가 무너진다.

**결론**: v1은 협의(화장품)로 확정. 광의 확장은 v2에서 별도 비교 분석으로 수행.

## 4. 분석 기간

**4년 (16분기)** — 종목별 상장 이력에 따라 불균형 패널.

예상 이벤트 수: 이력 긴 9종목 × 16분기 ≈ 144, 짧은 종목 ≈ 15~20, **합계 약 150~160**.

### 왜 1년이 아닌가
15종목 × 4분기 = 60 이벤트로는 독립변수 5개만 넘어가도 유의성이 나오지 않는다. 수집 코드는 동일하므로 기간 확장 비용이 거의 없다.

### 왜 4년에서 멈추는가
- DART 구조화 재무 데이터 하한이 2015 사업연도라 물리적으로는 10년까지 가능
- 그러나 기간이 길수록 레짐 변화 통제 부담이 커진다
- 4년이 표본 수와 관리 가능성의 균형점

### 4년으로 늘리며 발생하는 문제와 대응

| 문제 | 대응 |
|---|---|
| 레짐 변화 (업/다운사이클 혼재로 계수 상쇄) | **분기 고정효과 또는 레짐 더미 필수** |
| 생존 편향 | 현재 시점이 아닌 **과거 시점 기준으로 유니버스 구성** |
| 분할·합병·회계 재작성으로 재무 시계열 단절 | 이상치 자동 제거가 아니라 **원인 확인 후 개별 처리** |
| 상장 이력 짧은 종목의 베타 추정 불가 | **시장조정수익률 모델**로 폴백 (아래 참조) |

### 상장 이력이 짧은 종목 처리

에이피알(2024년 초), 달바글로벌(2024년 말)은 추정 윈도우 250거래일을 확보할 수 없다.

1. **시장조정수익률 모델 폴백** — 베타를 1로 고정하고 `AR = 종목수익률 − 시장수익률`로 계산. 추정 구간이 불필요하다. 두 모델을 모두 돌려 결과를 비교하면 강건성 검증이 된다.
2. **상장 후 첫 2개 분기 이벤트 제외** — 유통물량 부족, 과도한 변동성, 락업 해제 등으로 주가가 정상 상태가 아니다.

## 5. 데이터 소스

| 데이터 | 소스 | 가용 기간 | 비용 |
|---|---|---|---|
| 주가·거래량·시총 | pykrx / FinanceDataReader | 사실상 무제한 | 무료 |
| 공시 목록·접수시각 | DART OpenAPI | 1999~ | 무료 |
| 구조화 재무제표 | DART OpenAPI | **2015 사업연도~** | 무료 |
| 컨센서스(추정치) | — | **과거 시점 확보 불가** | — |

### 5.1 컨센서스를 사용하지 않는 이유 — 데이터 누수

무료/유료의 문제가 아니라 **시점**의 문제다.

네이버 금융·에프앤가이드 무료 페이지에서 컨센서스를 조회할 수 있으나, 표시되는 값은 **현재 시점 기준으로 갱신된 값**이다. "2023년 3분기 발표 직전에 시장이 기대한 값"은 어디에도 남아 있지 않다.

갱신된 현재값을 과거 이벤트에 결합하면 **look-ahead bias / data leakage**가 된다. 미래 정보로 과거를 설명하는 셈이다.

유료 단말(DataGuide, 퀀티와이즈)은 추정치를 시점별로 아카이빙하므로 과거 임의 시점의 컨센서스를 복원할 수 있다. 접근이 없으므로 사용하지 않는다.

**대안**: 컨센서스 대신 기대치 대리변수를 직접 구성한다.
- 과거 4분기 추세로 예측한 값 대비 실제 편차 (naive earnings expectation model)
- 발표 전 CAR[-20,-1] — 시장이 미리 반영한 기대의 직접 측정치

### 5.2 선반영을 오히려 이용한다

주가가 발표 전에 기대를 반영해뒀다면, 발표 직후 [0,+1] 구간에 남는 움직임은 정확히 **기대와 달랐던 부분**에 대한 반응이다. 예상대로 나온 실적은 발표 당일 주가를 움직이지 않는다.

즉 **CAR[0,+1] 자체가 이미 서프라이즈의 측정치**다. 컨센서스 숫자 없이도 시장이 대신 계산해준 셈이다.

**대가**: 실적 항목을 "예상된 부분 / 놀라운 부분"으로 분해할 수 없다. 시장이 이미 예상한 성장이 독립변수에 그대로 들어가므로 **회귀계수가 실제보다 작게 추정된다(희석)**. 유의성은 나오되 효과 크기는 과소평가된다. 한계로 명시한다.

**추가 활용**: CAR[-20,-1]을 독립변수로 투입하면 선반영을 통제하는 동시에 측정할 수 있다. 계수가 음수로 나오면 선반영이 작동한다는 직접 증거이며, 그 자체로 보고할 결과가 된다.

## 6. 특성(독립변수) 설계

### 6.1 원천 데이터 제약

DART 주요계정 API가 제공하는 항목은 다음뿐이다.

```
매출액, 영업이익, 당기순이익, 자산총계, 부채총계, 자본총계
```

판관비·재고자산·R&D비 등 세부 항목은 전체 재무제표 API가 필요하며 파싱 부담이 크다. v1은 주요계정으로 한정한다.

### 6.2 영업이익 성장률을 제외한 이유 — 계산식이 깨지는 지점

**문제 1: 분모가 음수일 때 부호가 역전된다**

기저가 적자면 관행적인 YoY 성장률 공식이 방향을 반대로 기록한다.

| 케이스 | 실제 의미 | `(t − t₄)/t₄` |
|---|---|---|
| −10억 → −20억 | 적자 2배 악화 | **+100%** (개선으로 기록) |
| −10억 → −5억 | 적자 절반 축소 | **−50%** (악화로 기록) |

정보가 없는 것이 아니라 **있는 정보가 반대로 들어간다**. 그리고 적자→적자 케이스는 영향이 작지 않다. 적자 축소는 턴어라운드 기대로 읽혀 주가가 크게 오르기도 한다. 단순히 결측 처리하면 **반응이 가장 큰 케이스를 골라서 버리는** 결과가 된다.

**문제 2: 분모가 0에 가까우면 값이 폭발한다**

절댓값 분모 `(t − t₄)/|t₄|`를 쓰면 문제 1은 해결되지만, 기저가 작으면 여전히 터진다.

| 케이스 (매출 1,000억 가정) | 실제 의미 | 원 공식 | 절댓값 분모 | 매출 대비 |
|---|---|---|---|---|
| −10억 → −20억 | 악화 | +100% ✗ | −100% ✓ | −1.0%p ✓ |
| −10억 → −5억 | 개선 | −50% ✗ | +50% ✓ | +0.5%p ✓ |
| −0.1억 → +3억 | 흑자전환 | +3100% ✗ | +3100% ✗ | +0.31%p ✓ |

이는 적자 문제가 아니라 **작은 분모 문제**다. 흑자 0.2억 → 5억도 +2400%가 된다.

**판단 경로**: 원 공식 → 부호 역전 발견 → 절댓값 분모 → 폭발 문제 잔존 → **매출액 정규화 채택**

**해결**: 영업이익 YoY 성장률을 특성에서 제외하고, 다음으로 분해한다.

```
영업이익 변화 ≈ 매출 성장(외형) + 마진 변화(수익성)
```

- **매출액 YoY 성장률** — 매출은 음수가 될 수 없어 부호 문제가 원천적으로 없음
- **OPM 변화폭 (%p)** — 비율의 차이라 적자여도 계산 가능. −5% → −2%면 +3%p로 정확히 개선으로 기록

얻는 것:
1. 적자 기저 결측이 거의 사라져 표본을 버리지 않는다
2. 매출 YoY와 영업이익 YoY의 다중공선성이 해소된다
3. "외형 성장이 중요한가, 마진 개선이 중요한가"로 해석이 선명해진다

### 6.3 최종 특성 목록 (8개)

| # | 특성 | 계산 | 역할 |
|---|---|---|---|
| 1 | 매출액 YoY 성장률 | (t − t₄) / t₄ | 핵심 — 외형 |
| 2 | OPM 변화폭 (%p) | OPM_t − OPM_t₄ | 핵심 — 수익성 |
| 3 | 영업이익 추세이탈도 | (실제 OP − 추세예측 OP) / 매출액 | 핵심 — 서프라이즈 대리 |
| 4 | 흑자전환 더미 | 부호 전환 여부 | 핵심 — 질적 사건 |
| 5 | 적자전환 더미 | 부호 전환 여부 | 핵심 — 질적 사건 |
| 6 | 발표 전 CAR[-20,-1] | 이벤트 스터디 산출 | 통제 — 선반영 |
| 7 | 로그 자산총계 ※ | ln(당분기 자산총계) | 통제 — 규모 |
| 8 | 장마감 후 발표 더미 | 접수시각 ≥ 15:30 | 통제 — 반응 시점 |

전환 더미(4, 5)는 연속 지표로 표현되지 않는 **질적 사건**을 포착하기 위해 별도로 둔다.

**※ 규모 통제변수 변경 (2026-08-12)**: 당초 로그 시가총액을 사용할 계획이었으나, 이벤트 시점 시가총액을 무료로 확보할 수 없어 **로그 자산총계로 대체**한다. 상세는 14.2 참조. 최종 확정 대기.

**다중공선성 주의**: 1·2·3은 서로 상관이 있다. 일부러 남겨두고 Lasso가 무엇을 죽이는지 관찰하는 것이 이 분석의 관전 포인트다. VIF를 반드시 확인한다.

### 6.4 전처리 결정 사항

| 항목 | 처리 |
|---|---|
| **4분기 단독 실적** | DART에는 4분기 항목이 없다. `연간(사업보고서) − 3분기 누계`로 역산 |
| **발표 시각 기준일 보정** | 접수시각 15:30 이후면 t=0을 다음 거래일로 이동 |
| **잠정실적 / 정기보고서 중복** | 잠정실적 우선, 없으면 정기보고서. 중복 제거 규칙 사전 확정 |
| **연결 vs 별도** | 연결(CFS) 고정, 없는 기업만 별도로 폴백 |
| **계정과목명 불일치** | "매출액 / 수익(매출액) / 영업수익" 등이 기업·연도별로 상이 → 외부 매핑 테이블로 표준화 |
| **극단값** | 1%/99% 윈저라이징. **자르기 전 상하위 값을 눈으로 확인**해 진짜 이벤트인지 데이터 오류인지 구분 |
| **결측** | 적자 기저 결측은 6.2 설계로 대부분 소거. 잔여 결측은 사유별로 기록 |

## 7. 모델

| 모델 | 목적 |
|---|---|
| **OLS** | 해석 — 계수 방향과 유의성 |
| **Lasso / Ridge** | 변수 선택 및 예측력 검증 |

### 7.1 왜 Lasso인가
- 표본 대비 변수가 많은 상황에서 정규화가 정석
- 재무 지표 간 다중공선성이 심함
- Lasso는 계수를 0으로 죽여 변수를 선택한다 → **"어떤 항목이 중요한가"라는 원 질문과 목적이 정확히 일치**
- 스케일에 민감하므로 피처 스케일링 필수

### 7.2 왜 부스팅을 쓰지 않는가

트리 앙상블 경험칙은 변수 1개당 관측치 50~100개다. 특성 8개면 **최소 400~800**, 여유 있게는 2,000 이상이 필요하다. 현재 표본은 약 150개다.

추가로, 주가 수익률은 신호 대비 잡음이 극단적으로 크다(R² 0.05면 양호한 수준). 이런 저신호 환경에서 부스팅은 신호 대신 노이즈를 학습한다. 금융 분야 ML 연구가 수십만 관측치를 쓰는 이유다.

> 표본이 150건이라 트리 앙상블은 과적합 위험이 크다. 정규화 선형모델이 이 표본 크기와 다중공선성 구조에 더 적합하다고 판단해 배제했다.

### 7.3 교차검증 — 두 번째 데이터 누수 지점

**일반 K-fold를 쓰면 안 된다.** 랜덤 분할 시 2025년 데이터로 학습해 2022년을 예측하는 상황이 발생한다. 미래 정보로 과거를 맞히는 누수다.

`TimeSeriesSplit`을 사용해 앞 기간으로 학습하고 뒤 기간으로 검증한다.

**누수 원칙이 파이프라인 양쪽 끝에서 일관되게 적용된다**
1. 수집 단계 — 컨센서스 시점 문제로 소스를 포기 (5.1)
2. 모델링 단계 — 시계열 특성 때문에 검증 전략을 변경 (7.3)

## 8. 로드맵

| | 범위 | 이벤트 | 분석 | 소요 |
|---|---|---|---|---|
| **v1** | 화장품 11종목 × 4년 | 약 150 | OLS + Lasso | 3일 |
| **v2** | K뷰티 20종목+ × 4년 | 약 320 | + 유형 더미, 상호작용, 정의 민감도 | +2~3일 |
| v3 (선택) | 코스피200 × 10년 | 약 8,000 | + 부스팅 | 1~2주 |

**v2와 v3의 확장 축은 다르다.** v2는 *정의* 확장(분석 질문 심화), v3는 *규모* 확장(모델 복잡도 확보). 섞지 않는다.

**v2에서 새로 가능한 것**: 브랜드 / ODM / 유통 / 메디컬 / 기기 유형 더미와 상호작용항. "어떤 항목이 중요한가"에서 **"어떤 사업 모델에서 어떤 항목이 중요한가"**로 질문이 한 단계 올라간다.

**v2에서도 부스팅은 불가**: 320개는 여전히 부족하다.

### v1 설계 조건 (v2 비용을 줄이기 위해 처음부터 지킬 것)

1. **종목 리스트를 코드 밖 CSV로 관리** — `포함버전` 컬럼으로 v1/v2 필터 전환, `유형` 컬럼이 v2에서 바로 더미가 됨

   ```
   종목코드, 종목명, 시장, 유형, 상장일, 포함버전
   090430, 아모레퍼시픽, KOSPI, 브랜드, ..., v1
   214450, 파마리서치,   KOSDAQ, 메디컬, ..., v2
   ```

2. **계정과목 매핑 테이블도 외부 파일** — 종목 추가 시 매핑만 추가

3. **DB 스키마에 유형 컬럼을 미리 포함** — v2에서 마이그레이션 불필요

## 9. 구현 방침

### 9.1 파이프라인

```
DART 수집 → 계정과목 표준화 → SQLite 적재 → 주가 수집
→ CAR 계산 → EDA → OLS → Lasso(TimeSeriesSplit CV) → 시각화
```

### 9.2 DB 스키마 (SQLite)

```
events  (종목코드, 분기, 발표일시, 매출액, 영업이익, 당기순이익, ...)
prices  (종목코드, 일자, 종가, 수익률)
market  (일자, 지수종가, 지수수익률)
```

SQL 레이어를 두는 이유: 데이터 분석 직군 공고 대부분이 SQL을 요구하나 pandas만 쓴 포트폴리오는 SQL 역량을 보여주지 못한다. 추가 비용 2~3시간.

### 9.3 코드 작성 원칙

- 설정값(종목, 기간, 윈도우, API 키)은 파일 상단 한 곳에 집중
- 함수 하나가 한 가지 일만 수행
- 단계별 중간 결과를 파일로 저장 (재실행 시 앞단 재수집 불필요, 눈으로 검증 가능)
- 단계마다 `shape`, `head()`, 결측 수 출력
- 주석은 **무엇을**과 **왜**를 구분해 기록. "왜" 주석이 면접 답변의 원본이 된다
- 학습 중에는 주석을 넉넉히 달고, 마지막 정리 단계에서 자명한 것을 걷어낸다

## 11. 포트폴리오 서술 방침 (데이터 분석 직군)

주식은 **소재**이고, 파는 것은 **데이터 파이프라인 구축 역량**이다. "주가 분석"으로 소개하면 면접관이 평가할 기준을 갖지 못한다.

| 원래 강조하려던 것 | 바꿔서 강조할 것 |
|---|---|
| 이벤트 스터디 방법론 | 시점 정합성 있는 패널 데이터 설계 |
| CAR, 초과수익률 | 노이즈 제거를 위한 벤치마크 차감 (한 줄로) |
| 어떤 재무 항목이 유의한가 | 이종 소스 조인 + 스키마 표준화 파이프라인 |
| 회귀 결과 해석 | 결측·이상치 판단 근거와 처리 이력 |

**최대 강점은 데이터 누수 서사**다. 수집 단계와 모델링 단계 양쪽에서 같은 원칙을 일관되게 적용한 경험은 교과서적 지식과 구별된다.

**30초 소개문**

> 기업 실적 발표 데이터와 주가 데이터를 결합해서, 어떤 재무 지표가 발표 직후 주가 반응과 관련이 큰지 분석했습니다. 데이터가 두 개 소스로 나뉘어 있고 발표 시각 단위로 정확히 맞춰야 해서, 수집·정합성 검증·표준화 파이프라인을 직접 설계한 게 이 프로젝트의 핵심이었습니다.

방법론은 상대가 물으면 그때 설명한다.

**주의**: 본인이 설명하지 못할 기법은 넣지 않는다. 회귀 하나를 제대로 해석하는 편이 복잡한 모델을 붙이고 얼버무리는 것보다 낫다.

## 12. 명시할 한계

1. 컨센서스 부재로 실적을 "예상된 부분 / 놀라운 부분"으로 분해할 수 없어 **회귀계수가 과소추정**될 수 있다
2. 표본 약 150건으로 통계적 검정력이 제한적이다
3. 단일 섹터 분석이므로 결과를 다른 섹터로 일반화할 수 없다
4. 일부 종목은 화장품 외 잔여 사업을 보유한다 (3.3 경계 사례)
5. 상장 이력이 짧은 종목은 시장조정수익률 모델로 폴백해 다른 종목과 산출 방식이 다르다

### 14.2 pykrx 시가총액 조회 불가 → 규모 통제변수 변경

`pykrx.stock.get_market_cap()`이 KRX 로그인을 요구하도록 변경되어 동작하지 않는다.

```
KRX 로그인 실패: KRX_ID 또는 KRX_PW 환경 변수가 설정되지 않았습니다.
Error occurred in get_market_cap_by_ticker: Expecting value: line 1 column 1
```

주가(OHLCV) 조회는 정상이므로 주가 수집에는 영향이 없다.
`FinanceDataReader.StockListing("KRX")`가 시총(Marcap)·상장주식수(Stocks)를 주지만 **현재 시점 스냅샷**이라 이벤트 시점 시총은 얻을 수 없다.

**검토한 선택지**

| 방안 | 비용 | 문제 |
|---|---|---|
| KRX 계정 생성 후 환경변수 설정 | 회원가입 | 로그인 방식 변경·차단 시 재현 불가 |
| 현재 상장주식수 × 과거 종가로 근사 | 0 | 증자·분할 이력이 있으면 왜곡 |
| **로그 자산총계로 대체 (채택 예정)** | **0** | 시장 평가가 아닌 장부 규모 |

**채택 근거**: 자산총계는 DART 주요계정에 이미 포함되어 추가 수집이 없고, **동일 분기 재무제표 값이라 시점 정합성이 완벽**하다. 근사나 우회가 아니다. 통제변수의 목적(규모 구분)은 충분히 달성된다.

README 기재 문안:

> 이벤트 시점 시가총액은 데이터 제약으로 확보가 어려워, 동일 분기 재무제표의 자산총계를 규모 대리변수로 사용했다. 시장 평가가 아닌 장부 기준이라는 한계가 있으나 시점 정합성은 보장된다.

### 14.4 베타 추정 가능 여부는 이벤트 단위로 판정해야 한다

`01_check_universe.py`의 초기 구현은 **종목 단위**로 "주가 확보 여부"를 판정해, 실리콘투(2021-09 상장)와 아이패밀리에스씨(2021-10 상장)를 통째로 시장조정모델 폴백 대상으로 분류했다.

그러나 실제로는 **2022년 하반기 초기 이벤트 몇 건만** 추정 구간 [-250, -30]이 부족하고, 이후 이벤트는 정상적으로 시장모델을 적용할 수 있다. 종목 전체를 폴백시키면 불필요하게 정보를 버린다.

**조정**: CAR 계산 단계에서 이벤트별로 추정 구간 확보 여부를 검사하고, 부족한 개별 이벤트만 시장조정모델로 처리한다. 어떤 이벤트에 어느 모델을 썼는지 컬럼으로 기록해 결과 해석 시 구분할 수 있게 한다.
